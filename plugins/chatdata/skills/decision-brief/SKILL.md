# Write what the decision-maker needs

Read [the working agreement](../../references/working-agreement.md) when using this skill. It defines source, privacy, execution, and evidence boundaries.

Lead with the recommended decision and how strongly the evidence supports it. Name the alternative, including doing nothing where meaningful. Tie the recommendation to the decision's cost, reversibility, timing, and uncertainty.

Keep observed facts, estimates, assumptions, and hypotheses distinct. Include the denominator and period for each important number. State effect size and uncertainty in language the reader can use. Do not turn an interesting association into a promised outcome.

Show the most important evidence and the strongest evidence against the recommendation. Translate uncertainty into a conditional action: what to do now, what to measure, and what result changes the decision. Use a bounded test when a reversible action can produce useful evidence.

Use everyday language. Remove claims that are only adjectives. Do not invent a quote, customer, benchmark, savings estimate, or sense of urgency. Preserve caveats that could change the reader's choice.

Deliver a brief with decision, evidence, limits, alternatives, and next action with an owner/deadline only when known. Link the local calculation and source record. Sending it to someone or publishing it is a separate action requiring authorization.

For helper commands and input formats, see [the runnable tools](../../references/tools.md) when needed. Resolve script paths relative to this skill: `../../scripts/analyze.py`.
